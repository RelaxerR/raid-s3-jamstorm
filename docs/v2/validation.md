## Повторяемые команды

Из корня репозитория:

```bash
python3 tools/check_project_structure.py
python3 tools/check_project_structure.py --baseline origin/main
git diff --check
```

Первая проверка проверяет уникальность GUID, наличие `.meta`, порядок сцен, пути/GUID Build Settings, ссылки на скрипты в сценах, локальные Markdown-ссылки, согласованность manifest/lock. Опциональный baseline дополнительно проверяет сохранность всех идентичностей ассетов исходной ветки. Проверка путей скриптов учитывает GUID компонентов URP, uGUI и Input System при наличии их пакетов в manifest. Полное разрешение ссылок проверяет импорт Unity.

На macOS с Unity Hub (закрыть именно проверяемый экземпляр проекта либо использовать отдельную копию):

```bash
UNITY=/Applications/Unity/Hub/Editor/6000.5.1f1/Unity.app/Contents/MacOS/Unity
"$UNITY" -batchmode -nographics -projectPath "$PWD" \
  -runTests -testPlatform EditMode \
  -testResults /tmp/raid-v2-editmode.xml -logFile /tmp/raid-v2-editmode.log
"$UNITY" -batchmode -nographics -projectPath "$PWD" \
  -runTests -testPlatform PlayMode \
  -testResults /tmp/raid-v2-playmode.xml -logFile /tmp/raid-v2-playmode.log
"$UNITY" -batchmode -nographics -quit -projectPath "$PWD" \
  -executeMethod SecondCatch.EditorTools.ProjectBuild.ValidateScenes \
  -logFile /tmp/raid-v2-validate.log
```

Для Windows development-билда при установленном Windows Build Support:

```bash
"$UNITY" -batchmode -nographics -quit -projectPath "$PWD" \
  -executeMethod SecondCatch.EditorTools.ProjectBuild.BuildWindows \
  -logFile /tmp/raid-v2-windows.log
```

Результат последней команды — `Build/Windows/SecondCatch.exe`. Билд сам по себе не подтверждает 60 fps, Windows playtest и готовность серого показа.

## Ручной сценарий

1. Открыть Boot, дождаться MainMenu, выбрать **New game** и **Выйти в рейс**. На лодке нажать E у руля и грести W, пока корпус не выйдет за две тумбы причала. S включает задний ход. Вернуться между тумбами и проверить загрузку HomePort с прежним HP.
2. В следующем рейсе проверить качку и дрейф, поднять парус на мачте через E и W. Удержать лодку на одном курсе и сравнить ход с парусом и без него. Коснуться рифа, скалы или мусора и проверить изменение HP. Довести HP до нуля и проверить единственный возврат, 18 HP, сброс тяги.
3. Опустить сеть, пройти первый косяк, поднять сеть и собрать рыбу ЛКМ. Проверить «Улов 10/100» и движение рыбы вместе с лотком при повороте. Причалить, открыть и закрыть лавку, продать рыбу и купить усиление. В следующем рейсе проверить «Улов 0/100» и усиленную тягу.
4. Собрать три косяка до «Улов 100/100». Проверить в отдельном проходе продажу всей бочки, а при гибели с полной бочкой проверить 50 рыб в порту. [Сеть и вместимость](entities/cargo.md) · [Продажа и улучшение](entities/port.md)

Проверка SampleScene отдельно: океан, спасательный круг и спавнер левиафана используют прежние GUID и API. Этот визуальный сценарий и окончательный Windows playtest требуют проверки в интерактивном редакторе/на Windows.

## Покупка древесины и ремонт S1

- `WoodPurchaseTests` проверяет цену, списание за одно действие, отказ в море и при недостатке монет, сохранение остатка между сценами и расход до нуля.
- `BoatZoneRepairTests` проверяет урон по каждой из пяти зон, восстановление HP одной зоны, расход и отказ ремонта, а также распределение повреждений после гибели.
- `WoodRepairVoyageTests` проходит из `Boot` через ловлю и продажу рыбы, покупку древесины и контакт с мусором. Тест подаёт клавиши через Input System, проверяет ввод E у руля и сети, прогресс над зоной, отпускание E, выход из радиуса, успешный ремонт и попытку при нулевом запасе. Морской HUD показывает расход, после причала тот же остаток виден в лавке.

Шаги для ручной проверки описаны в [порту](entities/port.md#ручная-проверка) и [на лодке](entities/boat.md#повреждения-и-ремонт).

Расчёты используют фиксированный шаг времени через те же методы, которые вызываются Update и LateUpdate. Случайный выбор ветра проверяется с seed 18011 и восстановлением Random.state. Порядок тестов произвольный, каждый создаёт собственные объекты или открывает нужную сцену.
