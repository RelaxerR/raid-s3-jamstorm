# Архитектура v2 и журнал решений

[Оглавление](../index.md) · [Источники](sources.md) · [Pipeline](loading-pipeline.md) · [Сущности](components.md)

Задача этой ветки — согласованный каркас интеграции одиночной игры. Игровые сцены содержат только корни контроллеров и временную техническую панель. Ручной морской уровень, физические контакты, производственный UI и полная реализация механик остаются следующими задачами [плана](scope.md).

```text
Assets/
  _Project/
    Art/ Audio/ Prefabs/ Settings/ ScriptableObjects/
    Scenes/ Boot, MainMenu, HomePort, HomeShallows, SampleScene
    Scripts/
      Runtime/ Application/ Game/ Boat/ Port/ Voyage/ Fishing/ World/ Spirit/ UI/
               Foundation/ Player/ Leviathan/   (совместимость прототипа)
      Editor/ Editor.asmdef
      Tests/ Tests.asmdef, SoloGameSessionTests, ScenePipelineTests
  Plugins/                 океан, погода, молнии
  StreamingAssets/         специальный корень Unity, не вложен в _Project
```

| Решение | Причина и следствие |
| --- | --- |
| A01. Одиночная игра, без сетевого слоя | Wiki явно вырезает кооп. Нет лобби, RPC, authority, сетевых ID и зависимости от Fusion. Старые типы сохраняются только для обратной совместимости. |
| A02. `_Project` с сохранением GUID | Соответствует §3.6 Wiki. Перенесены существующие каталоги; Plugins остаётся на месте, StreamingAssets обязан быть специальным корнем Unity. Assembly names Runtime/Editor/Tests сохранены. |
| A03. Boot — единственный владелец GameApplication | Постоянный корень живёт через DontDestroyOnLoad; сцены не создают менеджеры самостоятельно. Дубликат корня уничтожается. |
| A04. Последовательная Single-загрузка | Четыре небольшие сцены не требуют additive-сложности. Загрузка блокирует команды; состояние перехода фиксируется после завершения загрузки. Новый мир пока только один. |
| A05. SoloGameSession отдельно от Foundation.GameSession | Старые правила несовместимы: HP 100, бесплатное восстановление, общая куча рыбы, босс RUN/TIRE/ENRAGE. Новый API не наследует их. Не ломаем существующий LocalSessionHost. |
| A06. Данные и Unity-компоненты разделены | Модель без UnityEngine удобно тестируется; Rigidbody/камера/триггеры принадлежат сцене и не переживают переход. Состояние в памяти принадлежит приложению. |
| A07. Пока одна типизированная бочка | Минимум для серого показа. 100 рыб и 60 HP взяты из Wiki; переход к двум бочкам первого транспорта требует каталога видов. Цены 10/100, скорость x1.4 — временные значения, не утверждённый баланс. |
| A08. Возврат и гибель различаются | Обычный Dock сохраняет HP/груз. Гибель оставляет 30% HP, теряет половину груза один раз. Нечётная потеря округляется вверх — техническое решение до согласования. |
| A09. Панель IMGUI только для интеграции | Даёт проверяемые переходы без зависимости от арта и UI-ассетов. Продуктовый интерфейс планируется UI Toolkit, как в Wiki. Debug-сигналы явно подписаны. |
| A10. Сохраняем рабочий прототип | SampleScene, скрипты круга/левиафана и плагины не переписываются и не включаются в новый билд. Старое наличие Winch не означает включение эндгейма. |
| A11. Сохранения не имитируются | Continue возобновляет только текущую сессию в памяти. Новая игра сбрасывает прогресс. JSON-персистентность потребует версии схемы и проверки записи/чтения. |
| A12. Новые адаптеры не подключаем к незавершённому миру | BoatController, SeaEnvironment, FishSchool, SeaSpiritDirector — минимальные точки интеграции; сцены не выдают их за готовый геймплей. |

Новые папки называются по-английски, комментарии/XML-сводки игрового кода — по-русски. Каждый новый компонент описан в [реестре](components.md). При добавлении механики сначала уточнить её [этап](scope.md), затем контракт модели и владельца, затем сценовый адаптер и сценарий проверки.

Пакет `com.unity.multiplayer.center` сохранён как существующий редакторский инструмент; он не подключает мультиплеер к игре. Удаление неиспользуемых пакетов и ассетов — отдельная уборка после проверки интеграций.
