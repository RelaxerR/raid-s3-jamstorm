# Основа Second Catch

## Объём и структура

Основа соответствует четырёхнедельному RAID-плану, переданному лидером 15.11.2026. Кооп — целевой режим. Проверка двух Windows-ПК и передачи штурвала относится к S1. Сольный резерв требует отдельного решения лидера.

```text
Assets/Scripts/Runtime/
  Runtime.asmdef
  Foundation/
    SessionState.cs
    GameSession.cs
    LocalSessionHost.cs
  Player/                  существующий прототип
  Leviathan/                  существующий прототип
Assets/Scenes/            существующие сцены
Assets/Plugins/           океан, погода, молнии
Assets/Art/Models/
  Lifebuoy/               модель спасательного круга
  Leviathan/              модель и текстуры левиафана
```

Foundation входит в существующую сборку Runtime. Папки прототипов переименованы вместе с файлами .meta, их GUID сохранены. SampleScene остаётся существующей точкой запуска прототипа. Для проверки основы создайте собственную тестовую сцену и добавьте LocalSessionHost на пустой объект.

Имена папок проекта пишем на английском. Текст XML-сводок, обычных комментариев и названий `#region` в игровом коде пишем на русском.

## Сущности и интеграция

GameSession владеет BoatState, CargoHold, Wallet, HuntEncounter и станциями Helm/Winch. PlayerState идентифицирует участника строковым ID. Join разрешён в порту. Occupy атомарно занимает свободную станцию и освобождает предыдущую. Leave освобождает станцию отключившегося игрока. Release сбрасывает сохранённый ввод штурвала.

FishDefinition — неизменяемые стоимость и вес одного вида рыбы. CargoHold ограничен количеством. CatchFish принимает один улов при наличии места. Sell доступна в порту, очищает трюм и обновляет единый баланс. Повторная продажа пустого трюма ничего не начисляет. BuyUpgrade покупает один уровень один раз. BoatState.UpgradeLevel читает будущий адаптер движения, эффект улучшения пока должен задать геймдизайн.

Рейс проходит Port → Sailing → Hunting → Port. Dock принимает сигнал проверенного портового триггера только при Sailing. HuntEncounter содержит RUN, TIRE, ENRAGE и исходы Won/Failed. Tick получает шаг до 0.25 с и подтверждённое действие занятой лебёдки. Урон и натяжение задаются внешней симуляцией. Повторные команды после завершения не выдают награду ещё раз.

Пример первой интеграции Егора после Awake компонента LocalSessionHost:

```csharp
var session = host.Session;
session.Join("local-player");
session.Occupy("local-player", StationRole.Helm);
session.Depart();
session.CatchFish();
// HUD читает session.Cargo.Count.
session.Dock();
session.Sell();
```

HUD читает свойства и Revision, которая монотонно увеличивается при изменениях. Значение Revision не является номером сетевого пакета или сохранения. Состояния имеют публичное чтение и внутреннюю запись. Все команды исполняются последовательно на основном потоке Unity.

## Host Mode

LocalSessionHost предназначен для локальной интеграции. Fusion-адаптер создаёт GameSession только на StateAuthority, сопоставляет PlayerRef с PlayerState.Id, проверяет отправителя и доступ к команде. Клиент посылает намерение, хост проверяет роль и применяет изменение. Клиентский HUD получает реплицированные поля. Не принимайте ID игрока и денежные значения из непроверенного клиентского сообщения.

Адаптер должен исключать повторную обработку сетевого запроса по ID/последовательности. Повторная продажа пуста лишь до появления нового улова, поэтому защита транспорта от отложенного повторного запроса остаётся обязательной. Tick вызывается из authoritative simulation, winchHeld определяется по вводу оператора Winch. Движение Rigidbody, RUN pull, физика троса, RPC, реконнект и завершение сессии при уходе хоста — следующие точки интеграции.

## Временные правила прототипа

Стартовые значения — 20 рыб, 10 монет за рыбу, 100 за улучшение, 50 за охоту. Обычные фазы длятся 4 с, TIRE даёт 10%/с. ENRAGE один раз при 50%, затем RUN. Победа при 100%, обрыв при натяжении выше 100. При возврате лодка восстанавливается бесплатно, улов сохраняется. Эти правила выбраны для проходимой основы и требуют согласования с ГД. Автоматический урон ENRAGE и платный ремонт пока не подключены. Сохранения относятся к резервному объёму плана.

## Работа вдвоём

Lead Dev владеет интеграционной сценой, лодкой, станциями и сетевым адаптером. Егор подключает источник улова и HUD в собственной сцене/префабе. Ветки автора `relaxerr/<описание>`, ветки Егора `<никнейм Егора>/<описание>` — конкретный префикс согласовать с Егором. Короткие PR содержат проверяемый сценарий и результаты. Переносить ассеты только вместе с .meta.

## Применённые рекомендации Unity

- Используется существующая Runtime.asmdef, UI/физика подключаются через компонент. Сборки позволяют задавать зависимости явно. [Assembly definitions](https://docs.unity3d.com/6000.0/Documentation/Manual/assembly-definition-files.html)
- Настройки компонента — private SerializeField, состояние сессии создаётся в Awake. Сериализуемые поля и runtime-состояние имеют разные жизненные циклы. [Правила сериализации Unity 6.5](https://docs.unity.com/en-us/engine/6000.5/manual/scripting/compilation-and-code-reload/script-serialization/rules)
- Каталог видов можно позже перенести в ScriptableObject и копировать значения в FishDefinition при создании сессии. Общие ассеты подходят для конфигурации. [ScriptableObject](https://docs.unity3d.com/6000.1/Documentation/Manual/class-ScriptableObject.html)

## Проверка

15.11.2026 временный .NET harness прошёл проверки переполнения трюма, двойной продажи, повторной покупки, эксклюзивности станции, отключения игрока, победы, обрыва и повторного рейса. Все три новых файла скомпилированы с UnityEngine.CoreModule установленного Unity 6000.3.12f1, 0 предупреждений и ошибок. Это проверка C# и доступности API, импорт проекта и Windows-билд требуют указанного ниже прогона точной версией редактора.

Чистая C# модель проверяется отдельным временным .NET harness для двойной продажи, повторной покупки, эксклюзивности станции, отключения игрока и завершения охоты. Unity-компонент требует проверки в редакторе 6000.5.1f1. На текущем компьютере обнаружен только 6000.3.12f1.

В Unity 6000.5.1f1 дождаться импорта, проверить Console и компиляцию Runtime. Добавить LocalSessionHost в тестовую сцену, выполнить пример выше и два прохода охоты: победа и SetTension(101). После каждого исхода проверить повторный Depart, общий баланс и доступность станций. Затем собрать Windows-прототип и выполнить S1 с будущим сетевым адаптером на двух ПК.
